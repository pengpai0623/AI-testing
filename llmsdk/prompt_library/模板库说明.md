# Prompt 模板库说明文档

> 版本：v1.0 | 更新日期：2026-08-10
> 适用范围：LLM 业务通用 Prompt 模板管理、版本控制、安全防护

---

## 一、库概述

本模板库为自研 LLM 业务通用 Prompt 模板集合，覆盖 **对话总结、代码排错、结构化商品抽取** 三类高频场景；支持多版本灰度切换、Prompt 注入多层防御，通过工厂模式统一调度，业务无需手动修改模板源码。

### 核心能力
- **模板分层管理**：按业务场景分目录维护，同场景多版本隔离
- **工厂统一调度**：全局配置控制版本，业务层零分支判断
- **多层安全防护**：边界隔离 + 输入清洗 + Schema 约束

## 三、模块分类详情

### 3.1 对话总结 chat_summary

| 版本 | 类型 | 特点 | 适用场景 | 安全策略 |
|------|------|------|----------|----------|
| v1_zero | 轻量零样本 | token 消耗低，可配置字数/输出格式 | 短聊天、简单会话快速摘要 | `<USER_INPUT>` 内容隔离 + 前置关键词清洗 |
| v2_cot | 思维链增强 | 分步拆解关键信息，遗漏率低 | 长对话、多诉求复杂聊天记录 | 同 v1，强约束分步推理 |

#### 模板变量
| 变量名 | 说明 | 示例 |
|--------|------|------|
| `source_text` | 待总结原始文本（自动包裹隔离标签） | 用户聊天记录、新闻原文 |
| `limit_word` | 字数约束 | `60字以内` / `300字详细版` |
| `output_format` | 输出格式 | `纯段落` / `无序列表markdown` |

---

### 3.2 代码排错 code_analyze

| 版本 | 类型 | 特点 | 适用场景 | 安全策略 |
|------|------|------|----------|----------|
| v1 | 精简版 | 基础排错 + 输出双模块 | 简单语法、类型报错 | 用户代码放 user 侧入参 + 隔离标签 + 过滤混淆分隔符 |
| v2_CoT | 分步推理版 | 流程化排查逻辑，深挖隐蔽漏洞 | 复杂业务代码、多层调用 bug | 内置固定禁止项，禁止脑补新增功能 |

#### 模板变量
| 变量名 | 说明 | 示例 |
|--------|------|------|
| `role` | 分析角色定位 | `专业Python代码审计与排错工程师` |
| `base_rules` | 基础约束规则 | `精准定位语法错误、类型异常、逻辑漏洞` |
| `cot_rules` | CoT 分步推理要求（仅 v2） | 4 步拆解推理流程 |
| `output_format` | 输出格式要求 | `输出分为【推理过程】【修复代码】两块` |

> **注意**：待分析代码不写入模板占位符，放在 `chat_single` 的 `prompt` 参数（user 侧），减少重复渲染 + 降低注入风险。

### 3.3 结构化商品抽取 struct_extract

| 版本 | 类型 | 特点 | 适用场景 |
|------|------|------|----------|
| v2_fewshot | 少样本增强 | 附带示例约束 + 固定 JSON 输出 | 批量文本提取商品名、价格、标签 |

#### 模板变量
| 变量名 | 说明 |
|--------|------|
| `role` | 抽取角色定位 |
| `rules` | 抽取规则约束 |
| `shot_examples` | Few-Shot 标准样例 |

> 配合 `LLMStructClient` + Pydantic Schema 使用，强约束输出格式，降低注入逃逸概率。

## 四、通用安全规范（全模板统一执行）

### 4.1 边界隔离（核心防御）
- **System Prompt**：存放角色、规则、输出格式、CoT 步骤等固定业务逻辑
- **User Message**：用户原始输入、待解析文本、代码全部放在 user 侧请求参数
- **隔离标签**：所有待解析文本用 `<USER_INPUT>` 标签包裹，强制模型仅读取数据、忽略内嵌指令

```
<USER_INPUT>
{用户不可信内容}
</USER_INPUT>
```

### 4.2 前置输入清洗
调用 `prompt_safe.py` 工具：
1. 清理 `---` / `===` / `***` / ``` 等混淆分隔符
2. 正则匹配高危劫持关键词，拦截疑似注入请求

### 4.3 输出侧约束
- 结构化场景强制绑定 Pydantic Schema
- 敏感业务增加输出关键词校验，拦截系统提示词泄露

## 五、版本切换规则

### 5.1 配置位置
全局默认版本统一写在 `utils/constants.py` 的 `PROMPT_CONFIG` 字典：

```python
PROMPT_CONFIG = {
    "product_extract_version": "v2_fewshot",
    "code_analyze_version": "v2_CoT",
    "chat_summary_version": "v1_zero",
}
```

### 5.2 切换方式
业务代码通过 `prompt_factory.py` 工厂函数获取模板，自动读取配置取值：

```python
from llmsdk.prompt_repo.prompt_factory import get_chat_summary_template

tpl = get_chat_summary_template()  # 自动返回配置指定版本
sys_prompt = tpl.render(...)
```

修改 `PROMPT_CONFIG` 一处即可全局切换版本，无需改动业务代码。

### 5.3 线上扩展
线上环境可对接配置中心（Nacos / Apollo），远程覆盖本地默认值，支持热更新、A/B 灰度测试，无需重启服务。

## 六、新增模板扩展指引

### 步骤
1. **新建业务目录**：在 `prompt_repo/` 下新建业务子文件夹，添加 `__init__.py`
2. **编写模板类**：继承 `BasePromptTemplate`，定义 version / scene / template
3. **注册工厂函数**：在 `prompt_factory.py` 新增对应 `get_xxx_template()` 方法
4. **更新配置**：在 `constants.py` 的 `PROMPT_CONFIG` 新增版本配置项
5. **更新文档**：补充本说明文档对应模块信息
